# iPhone eSIM 远程管控（iphone-esim-control）

用一台常开的 Linux/macOS 主机 + 一根数据线，把一部 iPhone 变成**可被脚本与 AI 远程操控的设备**：
读屏、点按、改设置、建捷径、切 eSIM 卡、回报状态。**不越狱、不签名、不要 Apple ID、不装描述文件。**

配套的通知与短信通道由另一个项目 [nas-push-stack](https://github.com/your-accountness/nas-push-stack) 提供（iMessage 门铃、飞书群、iOS→安卓通知转发）。两个项目只通过 HTTP 端点联动，互不依赖对方代码。

```
        你（浏览器）                手机网关（NAS / hw）                iPhone
  ┌──────────────────┐        ┌────────────────────────┐      ┌──────────────────┐
  │ 2999 /phone 页面 │──入队──▶│ 队列 + 状态 + 飞书推送 │      │ 自动化：信息含     │
  │ 「换成这张」     │        │ /phone/cmd /state      │─────▶│ #phone on <卡>     │
  └──────────────────┘        │ /p/<token>/phone/report│◀─────│ 捷径：关闭其它三条 │
                              └────────────────────────┘ 回报  │      + 打开目标卡  │
                                          ▲                    └──────────────────┘
                                          │ 门铃（iMessage / 其他通道，可选）
                                          └──── nas-push-stack ◀── 门铃投递
```

## 这套东西由三层组成

| 层 | 在哪里跑 | 干什么 | 文档 |
| --- | --- | --- | --- |
| 控制层 | Mac / Linux 主机（USB 连着手机） | `iphone-control` 走 iOS 27 原生控制：无障碍读屏 + HID 点按 + CoreDevice 起 App | [01](docs/01-装机-mac上跑iphone-control.md) [02](docs/02-把手机交给脚本与AI.md) |
| 手机端 | iPhone 本身 | 5 条自动化 + 5 条捷径：收门铃短信 → 切卡 / 报告状态 | [03](docs/03-在手机上写捷径与自动化.md) |
| 服务层 | NAS / 云主机 | 队列、状态持久化、网页按钮、回报接口、结果推送 | [04](docs/04-服务端-队列状态与页面.md) |

## 与 nas-push-stack 的边界

- **本项目**：只管「怎么控制手机 / 怎么让手机自己动起来 / 怎么把状态和结果收回来」。
- **nas-push-stack**：只管「怎么把消息送到各个终端」——iMessage 门铃、飞书群卡片、iOS→安卓通知转发、NAS 侧 App 放行/屏蔽。
- 联动点只有两个：① 服务端调一次 `POST /notify/imessage_nas` 发门铃；② 服务端调一次飞书 `im/v1/messages` 报结果。两者的凭证与实现都在 nas-push-stack 侧，本项目只给出契约与占位符。

## 五分钟看懂要做什么

1. 准备一台 **常开的主机**（Mac 或 Linux），一根能传数据的线，一部 iPhone（本项目在 iPhone SE3 / iOS 27.2.1 上验证）。
2. 在主机上装 `iphone-control`（`cargo install --path apps/iphone-control`），确认 `doctor` 全绿、`status` 显示「就绪」。
3. 用自带的 MCP 小工具（`scripts/ic_call.py`）验证能截图、能读元素、能点按。
4. 在手机上建 **4 条切卡捷径 + 1 条查询捷径**，以及 **5 条「信息包含 #phone …」自动化**。
5. 在服务端跑队列 + 页面（端点见 [04](docs/04-服务端-队列状态与页面.md)），把门铃与飞书接到 nas-push-stack。
6. 打开网页点「换成这张 CARD_B」→ 手机自己关掉另外三条、打开 CARD_B → 回报 → 页面高亮 + 飞书收到 ✅。

## 已验证的事实（不是推测）

- iPhone SE3（`iPhone14,6`）iOS **27.2.1**，全程未越狱、未签名、未登录开发者账号。
- 切卡实测延迟 **7–12 秒**（门铃 → 自动化 → 捷径 → 回报 → 飞书）。
- 锁屏、静音、勿扰均不影响自动化执行与门铃投递；**只有低电量模式会推迟后台执行**。
- iOS 硬限制：**同时只能激活 2 条线路**，所以切卡必须是「关掉其它几条 + 打开目标」，且**不要用「设定默认号码」**（会弹系统模态，挡住下一次自动化）。
