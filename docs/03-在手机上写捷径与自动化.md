# 03 · 在手机上写捷径与自动化

目标：让手机「收到一条特定短信，就自己去做一件事，并把结果发回来」。建成后**不需要 Mac 在旁边**。

## 1. iOS 26+ 的自动化新模型（必须先懂这个）

- 自动化不再是独立面板，而是**写在捷径编辑器里**：`自动化` 成了动作库里的一个分类。
- `自动化` 标签页的 `+` 创建出来的其实是**一条新捷径**（编辑器标题「新建快捷指令」），里面加「触发器 + 运行快捷指令」两个动作就是自动化。
- 所以库里每条自动化也是一条捷径，命名建议 `切换cte自动`、`查询当前卡自动`。

## 2. 三条硬约束（违反任何一条都会「看着成功其实不动」）

1. **iOS 同时只能激活 2 条线路**。开启第 3 条时系统会弹「选取要关闭的电话号码」强制对话框，把自动化卡死。
   ⇒ 切卡捷径必须是 **先关掉其它几条 → 再打开目标**。
2. **不要用「设定默认号码」**。它每次成功都会弹系统模态「默认设置已更改 / 默认语音号码已更改」，唯一按钮「好」，**该模态会挡住下一次自动化的蜂窝操作**（实测下一条指令 40 秒仍 pending）。iOS 没有 API 能关这个提示。
   ⇒ 切卡语义改成「关闭其它三条 + 打开目标」，「当前在用哪张」靠 `last` 记录。
3. **每个自动化里的「运行快捷指令」要一次性授权**：首次触发弹「允许「运行快捷指令 N」运行另一个快捷指令吗？」，被别的模态挡住时会**静默不执行**。每条捷径首次跑还会弹「允许「捷径名」连接 <域名> 吗？」。

## 3. 切卡捷径的结构（每个目标卡一条）

```
关/开蜂窝号码  → 关闭 CARD_A
关/开蜂窝号码  → 关闭 PH
关/开蜂窝号码  → 关闭 CARD_D
开/关蜂窝号码  → 打开 <目标>
获取 URL 内容   → https://<host>/p/<token>/phone/report?ok=1&detail=<目标>&act=default&plan=<目标>
```

一共 5 个动作；回报 URL 是**静态**的（写死号码名），所以手机端不需要解析任何 JSON。
服务端收到后按 `act`/`plan`（或退化到只看 `plan`）匹配最老的待执行指令，并回写状态。

## 4. 查询当前卡的捷径（3 个动作）

```
查找蜂窝号码   （筛选：活跃状态）
合并文本       （分隔符 → 自定义 → 输入 ,   ⚠️ 用默认「新行」会把换行带进 URL，导致「请求超时」）
获取 URL 内容  → https://<host>/p/<token>/phone/report?ok=1&act=status&detail=[合并后的文本]
```

回报形如 `detail=CARD_A,US`，服务端拆成 `active` 数组，页面据此打 `● 在线`。

## 5. 建自动化的可复现点击链（375x667 点）

```
自动化标签 → + (188,634) → 分类「自动化」(74,318)
→ 点搜索框 (250,60) → 输入「信息」 → Other "信息"（y 随滚动变，必须 a11y 复核）
→ 触发器卡默认是「发件人 是 []」，必须改：点 enum (64,244) → 菜单选「信息」(133,336)
→ 该行变成「信息 包含 [文本]」→ 点文本 (150,244) → 输入触发词 → 下滑收键盘
→ 底部搜索 (188,562) → 输入「运行快捷指令」→ Other "运行快捷指令" (188,183)
→ Button "快捷指令" enum (152,318) → 选目标捷径 → 返回即自动保存
```

⚠️ 不把「发件人 是 []」改掉，会留一张 `配置"发件人"启用此自动化。` 的失效卡。
⚠️ 触发词要与门铃正文一致（门铃发 `#phone on CARD_B`，条件也写 `#phone on CARD_B`）。

## 6. 最终产物清单（4 卡时）

| 类型 | 名字 | 作用 |
| --- | --- | --- |
| 工作捷径 | `切换cte` / `切换hk` / `切换CARD_C` / `切换giff` | 各 5 动作：3 关闭 + 1 打开 + 1 回报 |
| 工作捷径 | `查询当前卡` | 3 动作：查找活跃 → 合并 → 回报 |
| 自动化 | `切换cte自动` / `切换hk自动` / `切换CARD_C自动` / `切换giff自动` | 触发词 `#phone on CT / CARD_B / PH / gif` |
| 自动化 | `查询当前卡自动` | 触发词 `#phone status` |

## 7. 为什么不用 plist 直接生成

试过：`shortcuts://import-shortcut?url=…` 在 iOS 27 上**一律报「提供的快捷指令URL无效」**（同一 URL 用 Safari 能下载）。可行通道是「Safari 下载 → 文件 App → 点开 → 添加快捷指令」。
但更硬的限制是：**蜂窝那几个动作是 AppIntent，参数序列化在 plist 里怎么写都不生效**（写进去编辑器显示空、运行时「请为此操作中的每个参数选取值」；条件分支在 plist 里也恒不成立）。
⇒ 结论：**蜂窝动作只能在 UI 上点**，plist 只适合做「纯 HTTP + 文本处理」那种捷径。
