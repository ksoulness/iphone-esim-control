# 05 · 门铃与结果通知（与 nas-push-stack 的联动）

服务端不会主动去「敲」手机，它靠**一条短信当门铃**把手机叫醒；结果则回到服务端，再由服务端推给飞书。
这两件事本项目都只给**契约**，实际通道由 [nas-push-stack](https://github.com/your-accountness/nas-push-stack) 提供。

## 1. 门铃：为什么用 iMessage 而不是 HTTP 推送

手机侧要「收到事件就自动跑捷径」，iOS 上能当触发器的只有几类：信息、邮件、App 通知、闹钟、NFC…
其中最稳、最可控、最便宜的是**给自己的号发一条短信**（iMessage 走网络，不花短信费），配一条「信息 包含 `#phone…` → 立即运行」的自动化。

服务端只做一次 HTTP 调用，把门铃交给 nas-push-stack 的 apprise 端点：

```bash
# 契约（占位符）：POST <NAS>/notify/imessage_nas
# body: 正文一行，例如
#phone on CARD_B
```

对应 nas-push-stack 里的实现是 `imessage_nas` 这个 key（NAS 直发 iMessage，走 8098 网关）。**本项目不含这段代码**，只要求：
- 调用成功（200）即认为门铃已发；
- 正文严格是 `#phone <动作> <卡名>`，动作取值 `on` / `off` / `status`；
- 手机端自动化的条件字符串与正文**前缀一致**。

## 2. 结果：飞书「短信」群

手机回报打到服务端后，服务端推一条飞书群消息：

```
✅ 切换成功｜iPhone：卡1 固定 US；卡2 由 CARD_B 切到 **CARD_A**（手机已执行）
❌ 切换失败｜iPhone：卡2 仍停在 CARD_B，切 PH 没成功（所选蜂窝号码当前未激活）
📶 线路状态｜iPhone：卡1 固定 US；卡2 当前 CARD_A
```

契约：`POST https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id`
- `receive_id` = 目标群 `chat_id`（在 nas-push-stack 的 `feishu.env` 里，形如 `oc_XXXXXXXX`）
- `msg_type=interactive`（卡片）或 `text`
- 凭证：`FEISHU_APP_ID` / `FEISHU_APP_SECRET` → `tenant_access_token`

本项目只给出这条调用与文案格式；**app 凭证、群 id、发卡片的实现都在 nas-push-stack**。

## 3. 看门狗：没人回报怎么办

指令入了队列、门铃也发了，但手机没跑（离线、关机、捷径被模态挡住）怎么办？
做法：`taken` 状态超过 **150 秒**没有 `report`，就置为 `failed` 并推飞书：

```
❌ 切换失败：切为默认线路 PH：手机 150 秒内没有回报（可能离线或捷径没跑起来）
```

这比「页面一直转圈」有用得多——你能立刻知道是手机那边断了。

## 4. 一条指令的完整时序（实测 7–12 秒）

```
00.0s  页面点「换成这张 CARD_B」→ GET /phone/cmd?action=default&plan=CARD_B
00.1s  入队 id=NN（pending）→ POST notify/imessage_nas 正文 "#phone on CARD_B"
00.3s  iMessage 到达手机
01-03s 自动化「信息 包含 #phone on CARD_B」触发 → 运行捷径 切换hk
03-07s 捷径：关闭 CARD_A / PH / CARD_D → 打开 CARD_B
07.2s  GET /p/<token>/phone/report?ok=1&detail=CARD_B&act=default&plan=CARD_B
07.3s  服务端：匹配最老 pending/taken → state=done → last=CARD_B → 推飞书
07.4s  页面刷新：当前挂卡 US + CARD_B，CARD_B 高亮
```

## 5. 可选：不用 iMessage 也能叫醒手机

门铃只需要「一个能让手机收到通知的通道」+「一条对应的自动化」。可替换方案：

| 通道 | 触发器 | 备注 |
| --- | --- | --- |
| iMessage / 短信 | 信息 包含 | 本项目默认，最稳、零成本（iMessage 免费） |
| 飞书 / Telegram / Bark | App 通知 | 需要「通知触发器」，且该 App 通知权限必须开 |
| 邮件 | 邮件 包含 | 稍有延迟，但可跨账号 |
| 轮询 | 个人自动化·时间 | 每 N 分钟拉一次队列，延迟高但完全被动 |

只要门铃正文和自动化条件对得上，后端代码一行都不用改。
