# 06 · 远程收 iPhone 短信与 App 通知

这一块**不归本项目实现**，归 [nas-push-stack](https://github.com/your-accountness/nas-push-stack)。这里只写「怎么接、边界在哪」，方便一起部署。

## 1. 原理（一句话）

iPhone 上一条捷径用 **「通知」触发器**（可选 41 个 App）→ 把 `[通知›App]` + 正文编码 → `GET https://<push-host>/p/<token>/ios2and?body=<编码后文本>`。服务端解码后按来源分发：短信 → 飞书「短信」群；App 通知 → 对应频道（安卓 ACE / 飞书等）。

## 2. 短信 vs App 通知的区别（服务端做的事）

| 类型 | 判定 | 落地 |
| --- | --- | --- |
| 短信（SMS） | 触发 App 是「信息」 | 模板 `[转发自iPhone] （SMS）[<发件人>]` + 正文 + `（时间 · 收件 <本机号>）` + `（HW）` |
| App 通知 | 其它 App | 标题 `（App名）标题`，**不带收件号码** |

NAS 侧还有两层过滤（属于 nas-push-stack）：
- `mobile-app-allow.txt` 有内容 = 白名单；`mobile-app-block.txt` 优先屏蔽；未剥出 App 名一律放行；原名与别名都匹配；改完 60 秒热生效。
- 41 个触发器 App 的清单维护在服务端页面 `/push` 的 iOS 区块里。

## 3. 部署顺序（两块拼起来）

1. 先按 nas-push-stack 把 iMessage 网关、飞书群、`/p/<token>/ios2and` 跑通；
2. 再在本项目的手机侧建「转发手机」捷径与「通知触发器」；
3. 最后按 [05](05-门铃与结果通知.md) 把门铃接到同一个 iMessage 网关上——**同一个网关，两个用途**（转发出去 / 叫醒手机）。

## 4. 与切卡的关系（重要）

- 切卡成功后，**新卡的短信会进到哪个号**取决于运营商的「默认语音/数据」设置；本项目刻意不设默认，只用「激活 2 条」的规则，所以**两条卡的短信都会到手机上**，转发捷径都能收到。
- 若某张卡未激活（被关掉），它收不到短信——这是运营商层面的，不是捷径问题。页面显示 `当前挂卡` 就是为了让你知道哪张在收。

## 5. 锁屏 / 静音 / 勿扰会不会影响

| 环节 | 影响 |
| --- | --- |
| 通知触发器 → 转发 | 不受影响（通知仍投递到通知中心） |
| 信息门铃 → 自动化 | 不受影响 |
| 飞书 / 其它 App 提醒 | 静音、勿扰只静音提醒，消息仍到达 |
| 低电量模式 | **会推迟后台执行**，这是唯一需要留意的 |
