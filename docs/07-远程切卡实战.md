# 07 · 远程切卡实战（一次点击的全链路）

## 1. 现场条件

- iPhone SE3 / iOS 27.2.1，插在 Mac 上（Mac 常开）；
- 4 张可切换卡 `CARD_A / CARD_B / CARD_C / CARD_D`，1 张常开卡 `US`，3 张纯流量卡；
- 服务端在 NAS，页面在 `http://<NAS>:2999/phone`；门铃走 iMessage，结果推飞书「短信」群。

## 2. 步骤（你自己只需要点一下）

```
打开 http://<NAS>:2999/phone
→ 看到「当前挂卡：US + CARD_A」，CARD_A 那张带 ● 当前
→ 点 CARD_B 那行的「换成这张」
→ 7–12 秒后页面显示「当前挂卡：US + CARD_B」，CARD_B 高亮
→ 飞书收到：✅ 切换成功｜iPhone：卡1 固定 US；卡2 由 CARD_A 切到 **CARD_B**（手机已执行）
```

## 3. 后台发生了什么（按顺序）

1. 页面 `GET /phone/cmd?action=default&plan=CARD_B` → 入队 `id=NN`；
2. 服务端发门铃：`POST <NAS>/notify/imessage_nas`，正文 `#phone on CARD_B`；
3. 手机收到 iMessage → 自动化「信息 包含 #phone on CARD_B」→ 运行捷径 `切换hk`；
4. 捷径：关闭 CARD_A → 关闭 PH → 关闭 CARD_D → 打开 CARD_B → GET `report?ok=1&detail=CARD_B&act=default&plan=CARD_B`；
5. 服务端匹配最老指令 → `state=done`、`last=CARD_B`、`active=['US','CARD_B']` → 推飞书；
6. 页面轮询 `state` → 高亮切换。

## 4. 查「现在挂的是哪两张」

点「向手机查询当前线路」→ 门铃 `#phone status` → 捷径 `查询当前卡`（查找活跃 → 合并 `,` → 回报 `CARD_A,US`）→ 服务端写 `active`，页面把仍在活跃的卡打 `● 在线`，真实在用的那张（`last`）打 `● 当前`。

> 为什么两个都要：`last` 是「服务端认为在用的」（用于高亮 `● 当前` 与「当前挂卡」那一行），`active` 是「手机真的还开着的」（用于 `● 在线`）。
>
> **手动切卡也能纠正**：如果你直接在手机「设置 → 蜂窝网络」里换了卡，页面暂时不知道；点一次「向手机查询当前线路」，服务端会用手机回报的活跃线路反推 `last`（`[phone] status sync phone_last: A -> B`），高亮立刻跟上。唯一例外：两张切换卡都关掉、只剩常开卡时，`last` 保持不变以免页面变空。

| 时间 | 指令 | 结果 | 耗时 |

| 早期 | 走「设定默认号码」的方案 | ❌ 模态挡住下一条指令 | — |

## 6. 失败了怎么读信号

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 队列一直 `pending` | 门铃没到手机 | 检查 iMessage 网关、手机是否在线 |
| `taken` 但 150 s 无回报 | 自动化跑了但捷径失败 | 看手机是否弹授权/模态；到手机上手动点一次捷径看报错 |
| 回报 `所选蜂窝号码当前未激活` | 目标卡没先打开 | 捷径顺序错：必须先「打开目标」再设默认（本项目已改为不做设默认） |
| 选项里找不到卡名 | `name` 与手机线路名不一致 | 改线路清单里的 `name` |
